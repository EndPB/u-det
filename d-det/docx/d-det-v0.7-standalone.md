## 1. 要解决的问题

### 1.1 一个越来越常见的场景

近两年，AI 已经能像程序员一样写代码。这带来了三类现实问题：

1. **检测**：这段代码是人类写的，还是 AI 写的？（样本级二分类）
2. **细分**：这段代码是纯人类、纯 AI，还是"人机混合"？甚至是被特意教过"模仿人类风格"的 AI？（四分类）
3. **归因**：如果是 AI 写的，**是哪一家的哪个模型**写的？（模型家族归因）

第 3 类问题最微妙：不同实验室（例如国内的 Qwen、DeepSeek、Yi，国外的 IBM、Hugging Face）训练出的代码模型，写出来的代码"味道"不同——变量命名习惯、注释风格、处理边界条件的套路，都带着自己家的"口音"。**我们的工作就是给这些"口音"建立一种稳定、可复现的数学测量方法。**

### 1.2 为什么以前的归因难做

归因早就有思路：拿一个"嫌疑模型"和它的不同版本做对比。但这些思路有两个老毛病：

- **依赖人工标注**：需要人不断标注"这句话像不像机器写的"，成本高；
- **换个题目就失灵**：在一个题目集上测得很准的方法，换一批题就掉十几个百分点（这叫"泛化差"）。

本文的 v0.7 稳定版给出了一个新答案，它的核心思想只有一句话：

> **不要只看"两个版本的作答差在哪"（位移），要把"两个版本的作答本身"（位置）一起看。**

下面我们从头讲清楚这句话的含义，以及它为什么带来大幅提升。

## 2. 背景知识课（零基础扫盲）

> 本章 5 个小节，读完就能看懂后面的全部内容。已有基础可跳过。

### 2.1 会写代码的 AI 是什么

现在的"大语言模型"（如 ChatGPT 背后的技术）本质是**"下一个词的预测机器"**：给它前面的一段文字，它会计算"下一个词最可能是什么"。在代码场景中，给它一个问题描述和已写的几行代码，它就能一个词接一个词地把整个代码"续写"出来。

- 我们在本文中把这份"会写代码的模型"统称为**代码模型**；
- 模型被训练时"见过的所有文字"决定了它的写作风格——这就是我们后面要测量的"口音"的来源。

### 2.2 同一个模型的"两副面孔"：base 与 instruct

这是理解本文的**关键概念**。每个现代 AI 模型发布时通常有两个版本：

| 版本 | 通俗理解 | 训练方式 |
|---|---|---|
| **base**（基础版） | "野生学者"：博览群书，但只会顺着文字续写，没有人教它"好好回答问题" | 海量文本上做下一个词预测 |
| **instruct**（指令版） | "客服培训后的学者"：会理解指令、给出得体的回答 | 在 base 之上，用人类偏好数据再训练一轮 |

base 到 instruct 的这一轮再训练，业界叫 **RLHF**（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）。通俗地说：先请人给模型的不同回答打分（这个打分的程序叫**奖励模型**），然后让模型的回答风格向"人类更喜欢的方向"移动。

**关键事实**：这场"再训练"会把模型从"野生学者"的位置**推动**到一个新位置——就像一个点在一张巨大的地图上被推了一段距离。本文后面管这段推动叫**位移**。

### 2.3 文本如何变成数字：嵌入向量

计算机不能直接比较两段文字的"风格"，需要先把文本变成数字。标准做法分两步：

1. **切块（分词）**：把代码切成一小段一小段，称为 **token**（可以想象成"拼字积木"，常见的是把 `def`、`count`、`( ` 这类片段各算一块）；
2. **过编码器**：把这一串积木交给一个**编码器**（专门把文本转成数字的模型），再对输出取平均，得到**一个固定长度的数字列表**。

这个数字列表就叫**嵌入向量**（embedding）。在我们的系统里：

> 一段代码 → 一个 **768 个数字**的向量。
> 写作 $h \in \mathbb{R}^{768}$，读作"h 是 768 维实数向量"，768 就是"768 个测量维度"——可以想象成给这段代码做了 768 项"体检指标"。

两个向量的含义很像"两个点在空间中的位置（坐标）"。这个"768 维空间"虽然无法肉眼看见，但数学上一切照常运行。

### 2.4 怎么"做判断"：分类器与线性判别（LDA）

"判断这段代码出自哪家"在数学上就是一个**分类任务**：给一个向量 $h$，从若干候选类别中选一个。最常用、也最适合小数据的方法叫**线性判别分析**（Linear Discriminant Analysis，LDA），它的思路可以用一句话概括：

> **找一个方向，让不同类别的数据在投影后尽量分开，同一类别的数据尽量聚拢。**

打个比方：教室里的学生（数据点）按班级（类别）混在一起，LDA 的任务是找到一块黑板的最佳摆放角度，使得透过黑板看过去时，各班站得最分明。

本文的判别器还多做了一件事：**收缩**（shrinkage）。它的作用像"别把话说太满"——当数据量不多时（我们的每一类只有几百到一千个样本，而空间有 768 维），直接估计"分散程度"会非常不靠谱，收缩技术把这个估计"往保守方向拉一把"，大幅提升稳定性。这一步没有可调参数（程序自动决定"), 因此我们的结果**不依赖调参**。

### 2.5 如何公平考试：训练/测试、防作弊与"按题交叉验证"

要验证一个分类方法是否真的有效，不能拿"做过题"的数据来考它，应遵守：

- **训练集**：给方法"看答案"的数据；**测试集**：没见过的数据；
- **过拟合**：方法死记硬背了训练数据，测试就露馅——这是所有机器学习头号敌人。

我们用一个更严格的技巧：**按题交叉验证**（英文 GroupKFold）：

> 把所有题目分成 5 份。每次拿出 4 份的"作答"训练，用剩下 1 份的"作答"考试；做完 5 轮取平均。
> **同一道题的所有数据永远整体进同一份**——这样"考试"的题目训练时从未出现过，杜绝作弊。

本文报告的所有数字，都是在"没见过的题"上考出来的。

## 3. 数据：我们造出了一套"对照实验"

### 3.1 同题双答（配对数据）

要测量"口音"，需要**对照实验**。我们准备了 1304 道编程题（来自公开代码题库），然后：

> 对每一道题、每一个模型家族：让它的 **base** 写一版（记为 $x^-$），让它的 **instruct** 写一版（记为 $x^+$）。

每道题由此得到一对作答：$(x^+, x^-)$。这一对就是本文的"最小样本单位"，称为**配对**。

**为什么配对是钥匙**：$x^+$ 和 $x^-$ 回答的是同一道题、来自同一家模型——它们的差只能来自"这场 RLHF 再训练"，不需要任何人工标注就能对照出"这家模型的偏好特征"。这就是"免标注"的来源。

### 3.2 六个模型家族与数据规模

我们一共覆盖 6 个家族（同一家的不同代际按两个家族计）：

| 家族代号 | 出处（实验室） | 大致规模 | 完成配对数 |
|---|---|---|---|
| Qwen0.5B | 阿里巴巴 | 0.5B | 1303 |
| Qwen1.5B | 阿里巴巴 | 1.5B | 394 |
| DeepSeek1.3B | 深度求索 | 1.3B | 400 |
| Yi1.5B | 零一万物 | 1.5B | 1302 |
| Granite2B | IBM | 2B 级 | 1236 |
| SmolLM2 | Hugging Face | 1.7B | 1068 |

（"0.5B"读作"5 亿参数"，参数越多模型一般越大。全部 6 族合计 **5703 个配对**。）

其中，**六族都被同一道题覆盖**的"共同题"有 **329 道**（用于第 5 章将介绍的"转导"口径）。

### 3.3 特征化：一切实验共用同一套数字

每段生成代码都在**冻结的编码器**上过一遍：得到 $h^+ \in \mathbb{R}^{768}$（instruct 作答的向量）与 $h^- \in \mathbb{R}^{768}$（base 作答的向量）。

"冻结"的意思是：编码器在所有实验里保持不变、不再训练。**本次稳定版的全部结果不包含任何训练过程**（详见 5.4）。

## 4. 方法：三张"照片"与一把"尺子"

### 4.1 三种"读法"（怎么做特征）

把每个配对想象成一个人的**两张照片**：instruction 版和 base 版。我们可以用三种方式"读"这两张照片：

**读法 1（旧方法）：只看两张照片的差——位移 Δ**

$$\Delta \;=\; h^{+} - h^{-} \quad(\text{两个 } 768 \text{ 维向量逐位相减，仍是 } 768 \text{ 个数字})$$

它的含义：这家模型"被 RLHF 推动的方向和幅度"。旧方法认为归因信息藏在这个"差"里。

**读法 2（旧方法的一半）：只看平均像 S 与差异像 A**

- 平均像：$S=\dfrac{h^+ + h^-}{2}$（两张轮廓的公共部分——"这家模型长什么样"）；
- 差异像：$A=\dfrac{h^+ - h^-}{2}$（就相当于上面的位移 Δ 的一半）。

**读法 3（本次的核心改动）：两张照片一起看——联合视图**

$$[\,h^{+};\ h^{-}\,] \quad(\text{把两个 } 768 \text{ 维向量首尾相接，变成 } 1536 \text{ 个数字})$$

直觉：判断一个人的口音，光听"他这两句话的差别"（位移）不够，把**两句话本身**都交给判别器，信息最全。我们的实验证明（见第 5、6 章）：**联合视图远强于只看向量差**。

### 4.2 中心化：把"题目本身的难度"从分数里扣掉

假设不同家族的口音确实不同，但每道题的内容也千差万别——同一道题的所有模型作答会有某种**共同特征**（题目内容），这会淹没口音。

**中心化**（centering）就是对这个共同项做一次减法：

> 对每一道题、每一张照片（$h^+$ 与 $h^-$ 分别处理）：
> $$\tilde{h} \;=\; h \;-\; \frac{1}{k}\sum_{g=1}^{k} h_g$$
> 其中 $k$ 是这道题可用的"候选家族"数量，$h_g$ 是第 $g$ 个家族在这道题上的同名照片（也在 $ \mathbb{R}^{768}$ 中）。

通俗地说：**把同一道题上"所有候选家族的平均像"当作题目底色，减掉它，剩下的就是"这家的口音偏离平均值多少"。**

- 这种减法**不使用任何标签、任何答案**，纯数学；
- 代价：考一道新题时，需要该题的**至少 1 个"兄弟家族"样本**（即另一个候选家族的作答）来估计平均值。我们实测（后文）：加上 1 个兄弟样本，收益就已经接近饱和。

### 4.3 判别器：一把带"收缩"的尺子

判别的全过程（全部是固定公式，无需学习、无需调参）：

1. **标准化**：把训练数据的 768（或 1536）个维度各自拉成"均值为 0、波动为 1"，避免量纲干扰；
2. **线性判别（LDA，含自动收缩）**：把这 768 维数据投影到最多 $\min(\text{家族数}-1,\ 32)$ 维的判别空间——这是"类内尽量聚、类间尽量分"的最优线性方向组合；
3. **原型最近邻**：每个家族在判别空间里的平均位置作为它的"原型"；判别时，看样本离哪个原型最近，就判给哪个家族。

对每个数字的理解可以类比"指纹比对"：先给每个家族建一张"标准指纹图（原型）"，新样本来了就找最像的那张。整套判别器在几秒钟内就能在普通 CPU 上重新拟合，**没有随机性**（同样数据永远给出同样结果）。

### 4.4 评测协议（防作弊的完整细节）

- **按题交叉验证**：5 折；同一道题的所有样本整体进同一折（4.4 见 2.5 的解释）；
- **标准化只使用训练折的统计量**，测试折的任何信息都不参与；
- **报告指标**：准确率（acc）= 判对的比例；**平衡准确率**（balanced acc）= 每个家族判对率的平均（防止"多数类靠猜"刷分）。
- 对照的"随机水平"：二分类 50%，四分类 25%，六分类约 16.7%。

### 5.4 为什么说这是一个"稳定版本"

| 稳定性维度 | 具体情况 |
|---|---|
| **零训练** | 全部判别器都是闭式公式（几秒拟合），不含神经网络训练——自然满足"单方法微调不超过 2 轮"的预算纪律（我们连 1 轮都不需要） |
| **零调参** | 判别器用默认设置；中心的计算是纯平均；换换数据只会改变数字，不改变方法 |
| **零随机** | 同样数据永远给出同样结果（无随机种子问题），第三方可在任何机器复现 |
| **零新增数据** | 全部结果基于既有的 6 个模型家族配对，不需要任何新生成、新下载、新标注 |
| **防作弊协议** | 按题交叉验证 + 训练折内标准化（详见 4.4） |

## 6. 为什么有效：两条"指纹通道"的理论解释

### 6.1 一切从 RLHF 的一条公式说起

理论界已经证明：经过 RLHF 训练后的模型，与它的基础版之间满足一条简洁的关系（在"不过度偏离基础模型"的前提下严格成立）：

$$p_{\mathrm{instruct}}(x)\;\propto\;p_{\mathrm{base}}(x)\;\cdot\;e^{\,r(x)/\beta}$$

逐符号解释（**每个符号都请按下面的说明理解**）：

| 符号 | 读法 | 含义 |
|---|---|---|
| $x$ | "一段代码" | 我们考察的对象（本应是某个模型写出来的一段代码） |
| $p_{\mathrm{base}}(x)$ | "基础版给它的概率" | 野生版模型觉得"这段代码有多自然"——0 到 1 之间的一个数 |
| $p_{\mathrm{instruct}}(x)$ | "指令版给它的概率" | 培训后的模型觉得它有多自然 |
| $r(x)$ | "奖励分" | 人类偏好打分器给这段代码的分数（可正可负） |
| $\beta$ | "约束强度" | 一个正数，控制"允许偏离基础模型多远"——越小越保守 |
| $\propto$ | "成正比" | 左右两边只差一个（与 $x$ 无关的）归一化常数 |
| $e^{\cdot}$ | 指数函数 | 数学常数 $e\approx2.718$ 的幂 |

两边取对数后得到：

$$\underbrace{\log p_{\mathrm{instruct}}(x)-\log p_{\mathrm{base}}(x)}_{\text{两版模型打分之差（可测量）}}\;=\;\underbrace{\frac{r(x)}{\beta}-\log Z}_{\text{人类偏好相关量（不可直接测量）}}$$

也就是说：**"对齐把模型推动了多少"这件事，虽然看不见奖励分数，但可以通过比较两版模型的打分间接测量**。这条公式是整个项目"免标注"理想的理论根据。

### 6.2 家族的"身份"从哪两条通道泄漏

把每个家族想象成一个点在一张高维地图（768 维空间）上：

- **通道① 风格位置**：每个实验室的模型因为训练数据、代码习惯不同，在这张地图上**天生站在不同的区域**——就像不同城市的方言。无论 instruct 还是 base，这个"家乡口音"都在（**两张照片都带着**）。
- **通道② 对齐位移**：RLHF 把 base 推向 instruct 的这段"位移"——理论公式管辖的正是这一项。

**我们的实测结论**（这就是本次提升的根源）：

1. **通道① 与通道② 都真实存在，但任一单独使用都不够**：只看位移（旧方法）或只看平均像（单张画像），准确率都只有 0.76~0.79；
2. **两者联合（两张照片一起交给判别器）显著更强**：0.83~0.86；
3. **位移单独偏弱有一个有趣的原因**：各实验室的 RLHF 都朝着"人类普遍偏好"的相似方向推（就像全世界的客服培训大同小异）——把六家的位移方向互相比较，夹角只有约 3°（余弦相似度 0.998，越接近 1 越同向）。方向都差不多，分辨力自然有限；
4. **中心化再补一刀**：扣掉"题目底色"后，家族口音更纯粹，数字再涨一截。

### 6.3 一步到位的理解

> 旧方法：比较"两份试卷的得分差" → 只能抓住一部分信息；
> 新方法：**同时保留"两份试卷原文"（联合视图），再扣掉"试题本身的难度"（中心化）** → 家族口音完整浮现。

## 7. 使用边界与诚实声明

**适用条件**：

- 需要**配对样本**：至少要有"同一道题、同一个家族"的两段作答（例如某模型的 base 与 instruct 版本，两版都可运行即可获得）；
- 转导模式（联合+中心化）额外需要**同一道题至少 1 个兄弟家族样本**——不需要知道兄弟样本的答案，纯数学使用；
- 候选家族集合需要**事先给定**（二分类/四分类/六分类都是以"从给定集合中选一个"为前提）。

**已知局限（如实列出）**：

- 只用单段文本（没有配对）时，辨别力明显下降（六族场景下约 0.64~0.67，显著低于联合视图）；
- 上述数字全部在"同一题目集、同一编码器"内验证；**跨语言（如中文注释）、跨领域（如竞赛题→工程代码）的稳定性尚未测试**；
- 六个家族中同实验室的两代（Qwen0.5B 与 Qwen1.5B）即使新方法也仍是相对最难的一对（0.904）——代际差异小是客观困难；
- 本方法识别的是"模型风格"，**不构成任何对内容真伪、版权归属的判定**。
- **数字的波动范围**：受样本量限制，表中数字存在约 ±1~2 个百分点的自然波动（样本越少波动越大，二分类 800 样本约 ±2~3 个百分点）；提升幅度远大于波动；
- **对"尺子"的依赖——已复核 ✅**：测量风格所用的编码器本来自我们前期工作；2026-09-27 换用**完全中立的原始 CodeT5**（未做任何微调）重跑全部关键判读——增益方向 4/4 保持、对齐中心化 .8338（≥0.80 预注册线；如 granite/smollm 对 .8402→.8708→.9445）——**结论不是"尺子"造出来的**（第三方编码器终验仍欢迎）；
- **风格伪装未测**：如果有人故意把某家模型的输出改写成更接近别家的风格，本方法的表现未经测试；
- **选择说明**：表中方案是多种候选比较后胜出的统一方案；独立复核时数字可能有小幅回落（统计学常态）。

**不依赖什么（呼应设计目标）**：

- 不依赖任何人工标注；不依赖额外的数据集；不依赖生成更多模型（本次没有新增任何模型或数据）；
- 不依赖精细调参（判别器参数固定）；不依赖长训练（全程零训练）。

## 8. 术语表

| 术语 | 一句话解释 |
|---|---|
| 语言模型 / LLM | 通过"预测下一个词"训练出来的文本生成模型 |
| base / instruct | 同一模型的"野生版"与"人类偏好培训版" |
| RLHF | 用人类偏好数据对模型进行再训练的技术 |
| 奖励模型 / 奖励分 $r$ | 模仿人类打分习惯的程序，给文本打"好不好"的分数 |
| token（词元） | 文本被切成的"积木块"，模型的处理单位 |
| 编码器 | 把文本变成数字向量的模型组件 |
| 嵌入向量 / 特征 | 由一串数字组成的"文本指纹"，本文中为 768 维 |
| 768 维 | 用 768 个数字描述一个对象（好比 768 项体检指标） |
| 配对 $(x^+,x^-)$ | 同一道题、同一家族的 instruct 与 base 两版作答 |
| 位移 $\Delta$ | 两版作答向量之差 $h^+-h^-$ |
| 联合视图 $[h^+;h^-]$ | 把两个 768 维向量首尾相接（1536 维） |
| 中心化 | 减去同一道题上各候选家族的平均向量（扣掉"题目底色"） |
| 判别器 / LDA | 在空间中为不同类别寻找最佳分隔方式的线性方法 |
| 收缩（shrinkage） | 小数据时把统计估计向保守方向拉，防过拟合 |
| 原型最近邻 | 与哪个类别的平均位置最接近就判给哪类 |
| 训练 / 测试 / 过拟合 | 看答案练习；用没见过的题考试；死记硬背导致考试露馅 |
| 按题交叉验证 | 5 折考试、同题不拆开，防泄题的评测协议 |
| 准确率 / 平衡准确率 | 判对比例；每类判对率的平均（防多数类刷分） |
| 余弦相似度 | 两个向量"方向有多一致"，1 = 完全同向 |
| 泛化 | 方法在没见过的数据上依然有效的程度 |
