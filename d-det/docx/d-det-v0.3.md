## 1. 为什么转向（v0.2 判定的更新）

1) **基线重定**（2026-09-23 下午起）：对照从自建隔离组 abA 换成**真基线 = 微调 CodeT5**——
   `base_codet5_ft`（全参 @2e-5）m4/test **0.9751 / 0.9756**（n=1926）；
   `base_codet5_tok`（全参 + 滑窗全长覆盖 + token 头，4ep）**0.9732 / 0.9736**（n=1940；line 0.7978 / chunk 0.5081 / token 0.8270）；
   u-det 主线 v0.4.4（4ep）0.9775。d-det v0.1.0（冻结底座 + 分块 LoRA，2.06M 可训）**0.9552 —— 落后真基线约 2pt**。
2) **归因定位**（`scripts/decompose_scores.py`，同一样本池）：下降在 **s1 / 编码器侧**
   （ref s1 −0.73pt、instruct −1.29pt vs abA）；且交叉融合矩阵**证伪 v0.1.0 的 $s_2$ 可迁移**
   （把 v0.1.0 的 $s_2$ 接到 abA/C3 的 $s_1$ 上，增益消失）。
3) **结论**：差距根源在**载体**（冻结底座 + 弱上下文 + 监督单一），不在损失微调 →
   单实验一击：①全参微调；②上下文 K 128→512；③token 级（hybrid）与 $s_2$（pair）并训；④掩码复原锚（MLM）。
   用户定范围：**先跑 2ep + 评测 + 探针**。

## 2. 设计：四路监督（同训）

| 监督 | 数据 | 读出 / 损失 | λ | 备注 |
|---|---|---|---|---|
| 样本 BCE → $s_1$ | m4（人 / AI） | w1 · mean-pool | 1.0 | 原有 |
| token BCE → `tok_head` | hybrid（token / 行级） | `tok_head(D→1)`，逐 token BCE（pad −100 忽略） | 1.0 | hybrid 样本标签恒 1，**不进样本损失**（对齐 u-det `sample_streams=[m4]`） |
| hinge → $s_2$ | pair（base / instruct） | w2（rank=1），margin=1.0 | 1.0 | 原有 |
| 掩码复原（辅助） | m4 | 15% token 掩码（`<extra_id_0>`）→ **绑定词嵌入**原位重建 | 0.2 | 新增；起点 CE≈13.2 |

保留：正交保险 cos²(w1, w2)，λc=0.05；池化 mean；`s2_rank=1`。

## 3. 配方与预算（`configs/ddet_v030.yaml`）

- **编码器**：`codet5blk` + `full_ft: true`（不注入 LoRA、12 层全解冻、dropout 随标准 train/eval 语义）；
  `block=512 / block_batch=8`（每前向 4096 token）；逐分片梯度检查点；`static/compile=false`。
- **优化**：lr 头 3e-4 / 编码器 **2e-5**（与微调基线一致）；grad_accum 8；warmup 5%；clip 1.0；bf16；2 epoch（OneCycle）。
- **可训练参数 109.6M**（CodeT5-base **encoder 本体**；"220M"是 seq2seq 全量口径）。
- **预算实测**：每 epoch ≈ **2.2h**（16069 step；每步 5 次前向 + 全参反传）；2ep + 评测 + 探针 ≈ 4.7h。
- **冒烟门槛**（`--limit 100`）：可训 109.6M ✓；loss_mlm 13.2→2.7、loss_token 0.70→0.38、s1 0.693→0.070 全部正常下降 ✓。

## 5. 工程记录

- **`full_ft` 实现**：`CodeT5BlockEncoder` 新分支——不注入 LoRA、`requires_grad_(True)`、`train()` 不强制底座 eval；
  新增 `input_embeddings()` 供 MLM 取绑定嵌入（vocab 32100，`<extra_id_0>`=32099）。
- **MLM**：15% 随机掩码 + 绑定嵌入原位 CE；起点 CE≈13.2（> ln V——编码器输出并非校准的重建头，属正常），2 epoch 后 2.74。
- **梯度诊断的逐条化**：容器 cgroup 限 30GB，m4 无截断 ⇒ 整批 pad 后一次回传在长样本上会 OOM-kill；
  梯度/辅助诊断一律**逐条 `autograd.grad` 累积**（不触碰 `.grad`，训练中途安全）或 batch=1。
- **工具竞态坑**：**"写脚本 + 启动脚本"不能同一并行批次发出**（会执行到空文件、秒退无日志）——依赖操作必须串行。
- **探针口径**：`probe_scale_verify.py` 增加 `--config`（对齐训练配置；此前硬编码 `ddet_base`）。
