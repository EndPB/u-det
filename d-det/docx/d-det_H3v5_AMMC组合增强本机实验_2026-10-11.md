# H3 v5：固定 parent 预算的 AMMC 类组合增强

日期：2026-10-11。状态：本机已完成；`augmentation_increment_not_established`；正式闸门仍为 `revise_data`。

## 研究问题与边界

在不增加 parent 数量和训练曝光次数的条件下，把训练代码的注释、空白和局部标识符做语法安全扰动，是否比原样本训练更有效？比较原始、单变换、组合变换三组，而不是只看模型是否超过被增强削弱的词法基线。

这是 v4 数据上的新探索性增强对照，不重开 C0–C3、旧 H3 GPU 诊断或已关闭的 v4 GPU 候选。v4 配对曾使用 dev 信息，因此不能称确认性实验；没有 project provenance，不能称 project-heldout。test 未读。

## 训练协议

- 8,384 个 train parent；每组 3 epoch，每个 parent 每个 epoch **恰好一次**。两折中分别只有 seen-generator AI 与全部 human parent 进入 train。
- 对每个 parent/epoch 独立请求 comment `.2`、whitespace `.3`、rename `.4`。原始组不变；单变换组从已触发变换中选择一个；组合组顺序应用所有已触发变换。
- 变换失败保留当前视图；不通过丢弃失败行或多加成功行改变 parent 权重。三组使用同一 parent 顺序、seed、优化器步数和模型容量。
- 接受依据是 parser/tree/token 对齐，Python 另核 AST；**只是安全 proxy**，没有执行语料代码。注释变换按 parser comment 节点工作，不宣称删除全部 Python docstring；空白变换只是轻度空行扰动，rename 只是保守局部改名。
- 原始组 25,152 次 identity 曝光；单变换组 9,589 次改变；组合组 11,097 次改变，其中 1,929 次接受至少两个变换。合计 10,243 个唯一改变代码。
- 编码器冻结为已有 CodeT5-small；512-token head/tail、24,000 字符上限、mean pooling。此实验检验冻结表示上的增强，不是 AMMC 论文系统的复现，也不是端到端微调。
- 2 个 generator-heldout 折 × 3 seed × 3 训练组 × detection-only/joint/joint-invariance，**54 个检测运行**；另外每组 3 seed 的已见七 generator task-heldout source-only，**9 个独立来源运行**。
- 每组各自训练同折 raw lexical 控制；组合组另做 masked lexical 控制。词法使用全文，神经编码器有长度上限，此限制明确保留。
- clean-dev 与 hard-negative dev 同时评估，均未增强；没有增加 dev 变换压力集。

组合 joint 相对原始 joint 的增量，在 fold0 clean/hard-negative 为 **−0.05/−0.15pt**，fold1 为 **+0.06/+0.24pt**，task 成对 bootstrap CI 全跨 0。原始到组合的 clean 词法控制下降约 2.12/0.99pt，模型基本未变，不能把“模型减词法控制”的差值扩大归因于模型学到了不变性。

source-only 的三 seed 平均 accuracy：原始 clean/hard-negative 为 `.1914/.2072`，单变换 `.1890/.2064`，组合 `.1907/.2081`。这只说明已见 generator 的弱可读性，不能称 unseen-generator 归因。

## 增强自身的捷径检查

probe 只在 train 内按 task 切分：1,694 个 fit task、402 个 heldout task。每个 parent 聚合三次曝光后再拟合，不把同 parent 的变体分到两侧。

| probe（row AUROC） | 单变换 | 组合 |
|---|---:|---:|
| requested mask | .5047 | .5047 |
| accepted mask | .5342 | .5587 |
| 变换前后格式/长度变化 | .5424 | .5422 |

请求随机化没有明显标签信号，但变换的可接受性仍与标签相关。固定 parent 曝光避免了成功变体被额外加权，并没有消除接受率或格式痕迹的偏差。task-bootstrap CI 与逐 parent probe 分数另存于证据包；以上 row 指标不与 task-macro 混用。

## 裁定与下一步

本轮 `augmentation_increment_not_established`：该保守增强实现未带来冻结模型的稳定增量，不能写 H3 主结果。也不能推断 AMMC 或端到端增强无效，更不能只因词法分数偏高就认定全部信号都是捷径。

本机下一步应直接检验**增强对编码器训练的作用**，先按本机 4GB 资源测量可行性，冻结原始/组合两组的相同 token、parent 和更新预算，再做成对微调及变换压力评估。语法安全、accepted-mask 残留偏差与原始 clean-dev 均需保留报告。只有实测本机资源不足的完整训练矩阵才移交 AutoDL；不把本轮 63 个小头实验再次送服务器执行，不为小实验制作 GPU 指导。
