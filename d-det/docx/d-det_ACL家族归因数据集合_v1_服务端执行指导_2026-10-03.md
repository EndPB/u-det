# ACL 家族归因数据集合 v1：服务端执行指导

## 目标

这次服务端工作不是继续堆叠 SupCon，而是建立可复现的多来源实验台，回答三个问题：

服务器端 AI 的逐步执行版本见 [AutoDL 服务器端 AI 下一阶段执行指导](d-det_AutoDL_服务器端AI下一阶段执行指导_2026-10-03.md)。本文件保留数据集合说明和协议约束；执行时优先阅读新的逐步指导。

1. AICD 的大规模 Task 2 上，模型是否能达到强基线并稳定区分家族；
2. 这种区分是否依赖任务、语言、仓库或某个具体 generator；
3. 在 generator 留出和跨来源测试下，是否仍有可迁移的家族信号。

## 阶段 A：数据和标签审计

服务器 AI 先完成以下只读检查：

- 读取 `collection_manifest.json`，确认四个来源的许可证和用途；
- 对 AICD 逐 shard 检查行数、列名、数字标签分布，禁止整体 `read_*`；
- 从 AICD 官方协议复核数字标签到 human/11 family 的映射，证据写入 `aicd_label_map.json`；
- 检查 AICD train/validation/test 的 exact code hash 泄漏；
- 检查 STACAD 以 `file_name` 为 group 的五折完整性；
- 检查 Droid 的 generator/family 计数和每个留出折的训练覆盖率。
- 检查 AuthorBench DCAN core 每个 `task_id` 是否至少覆盖两个 family，并确认 task split 没有泄漏。
- 检查 CoDET-M4 的 `model/target/language/source` 分布；它不作为同语义正对数据。
- 检查 LLM-CodeGen 的 `task_id=scenario:cwe_id` 是否跨模型覆盖，并把 simple/secure 作为场景变化而不是新的 family。

若 AICD 的标签映射无法从官方发布材料独立确认，先保留数字 ID，暂停所有“某家族胜负”的文字结论。

## 阶段 B：强基线

在 AICD Task 2 原始官方切分上固定以下基线：

- TF-IDF 字符/词 n-gram + 线性分类器；
- CodeBERT 或 ModernBERT 的截断分类器；
- 一个轻量级 pooled embedding + logistic regression；
- majority、uniform 和 per-language majority 参考线。

记录 Macro-F1、balanced accuracy、每类召回、混淆矩阵、ECE，以及按语言分层的结果。先只取固定的短代码长度上限做冒烟实验，再扩展到完整训练预算。

## 阶段 C：本项目方法

方法分三视图：

1. **语义视图**：编码代码任务/行为；
2. **来源视图**：建模 generator-specific fingerprint；
3. **任务条件化残差**：在同一 task/repository group 内比较来源差异。

训练时使用来源内正对和跨 generator 正对，但评估必须同时给出：

- AICD 官方 in-domain；
- AICD 语言或域变化；
- Droid generator-held-out；
- STACAD file-held-out；
- AuthorBench task-held-out。

任何增益都必须相对同一 backbone、同一采样量、同一切分的强基线，并给出至少 3 个随机种子或 bootstrap 置信区间。

## 阶段 D：SOTA 判定门槛

只有在以下条件同时满足时，才写“达到 SOTA”或“显著优于基线”：

- 复现公开基线的协议、切分和预处理；
- 主指标在官方测试集上提升，且置信区间不跨零；
- generator-held-out 与 task/repository-held-out 没有同步恶化；
- 去掉任务 ID、语言提示、长度等捷径后结论仍成立；
- 所有来源、许可证和标签映射均可追溯。

如果只在 AICD 官方切分提升，而跨 generator 或跨任务下降，论文应把它写成闭集改进，并把泛化失败作为分析结果。

## 禁止事项

- 不把 AICD、Droid、STACAD、AuthorBench 的数字标签直接拼接；
- 不把 Droid 的无 task_id 数据写成同题 H2 证据；
- 不将 AICD 的数字标签按猜测命名；
- 不为了提高分数随机切分同一个文件、同一个任务或同一个仓库；
- 不重新发布受限许可证数据的合并副本。
