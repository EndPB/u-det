# H3 本机修订 v2 结果与下一轮数据指导

版本：2026-10-11  
状态：`revise_data`；旧 H3 GPU 诊断批次已关闭，不在旧冻结包上重跑。

## 1. 本轮真正完成的工作

本机 CPU 阶段完成了一个独立的 v2 数据审计，不读取 test，也没有把 AutoDL 当作低显存执行环境：

- 从 v1 train 全量拟合每种语言的 `log1p(bytes)` 四分位边界，并冻结到 manifest；
- 为每个 dev task 保留 human 与最多三个不同 generator 的最近长度 AI，生成 2,636 行、659 个 task 的 `controlled_dev_v2`；原始 clean-dev 仍单独保留，不能用 controlled-dev 掩盖它；
- 将变体接受率按 `label × language × generator × length_bin` 展开，并进行 task-heldout view probe；
- 将 v1 parser 失败按语言、标签和 generator 分层，保留失败行，不用 parser-valid 子集偷偷替换主数据；
- 对 clean-dev 与 controlled-dev 都重新跑长度/词法轻量控制，所有结果和哈希写入独立证据目录。

脚本：`scripts/h3_local_revision_v2.py`。  
证据：`d-det/artifacts/h3_local_revision_v2_2026-10-11/`。  
派生 controlled-dev：`d-det/data/h3_stacad_revision_v2/controlled_dev_v2.jsonl`（gitignore）。

## 2. 结果

| 评估视图 | 长度 task-macro AUROC | 词法 task-macro AUROC |
|---|---:|---:|
| clean-dev（5,272 行） | .7248 | .9694 |
| controlled-dev v2（2,636 行） | .6679 | .9585 |

controlled-dev 的长度读数已经低于 .70，但 untouched clean-dev 仍高于 .70；两个视图的词法控制都很高。view probe 的 task-macro AUROC 为 .5569，接近机会水平。parser 失败已分层记录，失败行仍留在建模候选中。project/repository provenance 仍未随 STACAD alignment 包提供，因此不能认证 project-heldout。

## 3. 闸门裁定

`formal_gpu_ready=false`，裁定为 `revise_data`。本轮没有生成 GPU `batch_manifest.json`，没有上传服务器，也没有读取 test。旧 GPU 诊断的同折 lexical 控制已经证明旧冻结包不存在有效增量，因此不得以“再跑一次”替代数据修订。

## 4. 下一轮必须先完成的事情

1. 补齐可审计的 repository/project provenance，并将 project cluster 纳入 split；没有来源证据时，结果只能写 task-heldout。
2. 在不改变 clean-dev 的前提下，构造真正的 label×language×generator×length_bin 平衡 train 视图；controlled-dev 作为第二个预注册挑战集同时报告。
3. 对 lexical probe 做同折、同 split 的强控制，并保留词法基线；只有主模型在 clean-dev 和 controlled-dev 都相对该基线有预注册增量，才进入 GPU 主批次。
4. 重新运行 parser/duplicate/variant/view probe；变体 probe 必须继续接近机会，跨 split 重复仍为零或逐项裁定。
5. 以上条件通过后，才一次性冻结数据包、脚本、环境、`batch_manifest.json` 和 `SHA256SUMS`，安排至少两个 generator-heldout 折、三个 seed、完整 job 矩阵，统一上传和统一回传。

AutoDL 只接收新的、形式上通过闸门的冻结包，负责高显存训练和批量 GPU 实验；本机继续直接完成数据构建、解析、哈希、TF-IDF、轻量 probe 和包验收。


## 5. 词法捷径分解（追加诊断）

为决定下一轮数据构造，本机又对四种词法视图做了同口径 CPU 分解：

| 视图 | clean-dev task-macro | controlled-dev task-macro |
|---|---:|---:|
| raw | .8969 | .8500 |
| 去注释 | .8853 | .8543 |
| 空白归一化 | .8902 | .8374 |
| 标识符/字面量掩码 | .8471 | .7997 |

掩码后仍明显高于机会，说明剩余捷径来自 token 组合、结构模板、任务/来源差异的联合，而不是单独的注释或长度。下一版不能只继续调长度；必须补齐 project provenance，并按同题、同语言、同长度和 project-heldout 构造 hard-negative 配对。证据目录为 `d-det/artifacts/h3_lexical_diagnostic_v2_2026-10-11/`，仍不触发 GPU。
