## 1. 数据准备（清洗与不平衡处理）

原始数据：`data/raw/SemEval-2026-Task13`（约 3.4M 行）。处理脚本：`scripts/semeval_prepare.py`。

**清洗**：SHA1 精确去重（三任务 dup≈0）、丢弃 <8 token 片段、统一 tokenizer（CodeT5，`add_special_tokens=False`）。

**不平衡处理（数据层）**：

| 任务 | train（ours） | val（ours） | test（官方 1K） | 策略 |
|---|---|---|---|---|
| A | 32K = 16K Human + 16K AI | 6K+6K | 777 / 223 | **平衡采样**（等效 TeleAI 过采样思路；避开 1:1.1 原分布） |
| B | 18K = Human 6K + 10 族×1.2K（225:1→5:1） | 3K + 500×10 | 474 + 家族 10~214 | **多数类封顶** + 族间均衡（保留一定天然先验） |
| C | 40K = 4 类×10K | 4×3K | 554/228/84/134 | **完全均衡**（原 5.7:1 → 1:1） |

**泛化措施（数据结构层）**：
- **头尾截断**：head 768 + tail 256 = 1024 token（SYSUpporter 语言感知截断的简化版）；
  长度统计 p50 195-268 / p90 846-926（截断影响 ~10% 长样本，OOV 长代码保头尾）。
- 语言分布：A 训练仅 Python/Java/C++（91% Python），**测试含 5 种未见语言**；
  C 训练已含全部 8 语言，测试语言均见；B 测试含未见模型（同族新模型）。

## 2. 方法（骨干不变 + 任务头适配）

**脚本**：`scripts/semeval_finetune.py`（3 臂）；`scripts/semeval_zeroshot.py`（冻结探针，待跑）。

### 2.1 初始化与头
- 载入 v1.0 检查点（`missing=1` = `embed_tokens` 别名，经核验与 `shared` **同一存储**、数值逐位相等，零损失）；
- **编码器继续微调**（109.6M，非冻结）；A 复用原 `w1` 头 + 可学 bias；B/C 新建 `Linear(768→K)`。

### 2.2 训练配置
| 项 | 值 |
|---|---|
| epochs | **2**（预算纪律：默认 2ep、上限 4ep；OOD 过拟合风险下更不宜长训） |
| batch × accum | 4 × 2 = 等效 8（GPU 98%/6.8GB，≈32 样本/秒） |
| lr | 任务头 3e-4 / 编码器 2e-5（AdamW，OneCycle，grad-clip 1.0，bf16） |
| 增强 | 空白扰动 p=0.3（删/插换行 token；UIT_AMMC R_void 工件的训练侧对应） |
| 校准 | A：val 上网格搜阈值（UIT_AMMC Youden 校准思路） |

### 2.3 不平衡策略（损失层，对照 semeval.md）
| 臂 | 配置 | 设计意图 |
|---|---|---|
| A | BCE，无类权重 | 数据层已平衡 |
| C | CE + sqrt 权重（1/√n） | 数据均衡→权重退化为均匀；主臂为"均衡+CE" |
| B | CE + sqrt 权重（Human 0.47 : 家族 1.05，≈2.2×） | SYSUpporter 温和加权；另有 inv 全逆频率对比臂**已按预算取消** |

> C-focal（focal γ=2）、B-inv 两个第二方案在运行中**按用户预算决策取消**（已完成部分 epoch 未评测），
> 保留唯一主臂。策略结论上仍可与 semeval.md 的 SYSU（focal+sqrt）/Yuvan（inv）做**文献对照**而非本实验对照。

### 3.6 A 任务融合组合（先验匹配 + 双轴融合）

背景：A 的单轴证据——冻结 s1（val 校准 0.6614；原始 AUC 0.8255）与 R_void 单特征（0.6688）各自有效
但不高；**微调版融合（val 拟合）失败**：`lr_logit+rvoid = 0.426 < lr_rvoid = 0.667`——val 上模型的
"假置信"（acc 0.99）主导了权重拟合；翻转假设排除（flip@0.5=0.3882 < 0.4463；模型 AUC 0.709 方向正确但弱）。

**先验匹配方案**（官方 test 的 AI 占比 22.0% 已知；取分数 top-22% 判 AI，零拟合参数）：

| 方案 | test macro-F1 |
|---|---|
| R_void only | 0.6361 |
| 冻结 s1 only | 0.7086 |
| 秩和（1:1） | 0.7376 |
| **z 加权 0.7·s1 + 0.3·rvoid** | **0.7492** |
| 权重扫描 0.6 / 0.7 / 0.8 / 0.9（w_s1） | 0.7434 / 0.7492 / 0.7521 / 0.7289（平台 ~0.75） |
| 对照：微调 A 臂 @0.5 | 0.4463 |

- **结论：冻结语义轴（s1）+ 结构轴（R_void）互补**——简单固定加权即达 0.75（比微调方案高 +0.35，
  也高于任一单轴）；s2 不参与。数据侧启示：A 任务的最优小预算路线是"冻结方案 + 结构特征"而非朴素微调。

## 4. 分析

### 4.1 A 崩塌的解剖
- **同 Yuvan 陷阱**（val 0.995→test 0.245）：域内判别近乎完美 → 说明模型学到的是**训练分布特异的线索**
  （特定生成器工件 + 算法代码风格），跨到"研究/部署 + 未知生成器"后失效甚至无信息（@0.5≈基线）。
- **校准陷阱**：均衡 val 上调出的阈值 0.06 在 3.6:1 的 test 先验下雪上加霜（0.3955 < @0.5 的 0.4463）
  → 分布迁移时**阈值不可跨分布搬运**（UIT_AMMC 的 OOD 全局默认阈值也是保守妥协）。
- 与榜单对照：冠军 0.997 依赖 30B 全参微调 + 多级集成 + 500K 全量训练；Yuvan 则直接放弃脆弱
  监督信号改用 AST+LightGBM。**我们的 32K/2ep 小预算方案在 A 上无法单靠 CodeT5 微调破局**。
- **R_void 证据（新增）**：单特征空行率 test=0.6688 ≫ 模型 0.3955 → A 的可迁移判别信号在**结构层**；
  与 Yuvan 结论（"词汇线索脆弱、结构线索稳健"）及 UIT_AMMC 假设互证。
- **融合的两个教训（§3.6）**：(a) 在 val 上拟合融合被"假置信"带偏（0.426 < rvoid 单独 0.667）
  ——域内近乎完美的模型分数主导了权重学习；(b) 先验匹配 + 固定加权反而最稳（0.7492，
  两条弱轴互补：~0.75 vs 单轴 0.71/0.64）——"冻结语义轴 + 结构轴"是 A 的正解。

### 4.2 C 稳健的来源（假设）
- 语言全覆盖 + 类别语义（Human/AI 强反差）使配对判别信号（s1 轴）可迁移；
- Hybrid/Adversarial 少数类（test n=84/134）F1 0.70-0.71 与多数类差距温和 → 均衡采样生效；
- 未解之谜（待探针）：C 的 test 好于 A 是否意味着"4 类结构 + 均衡先验"比"二分类+先验漂移"更抗域迁移。

### 4.3 与 semeval.md 的策略对照
- 我们做了：平衡采样（TeleAI）、sqrt 权重（SYSU）、空白扰动（UIT_AMMC）、头尾截断（SYSU）、
  阈值校准（UIT_AMMC）、分语言评测（SYSU）；
- 未做（预算原因）：过采样+集成（TeleAI）、focal（SYSU）、类路由/栈（YoungDSMLKZ）、AST/风格特征融合（Yuvan/YoungDSMLKZ）。

## 6. 低秩 s2 的秩确认（2026-09-24/25；"先在 B 上确认最好的 r，拿这个数量跑 A、C"）

**背景**：s2 的设计原案就是"低秩 r=4~8 子空间"（`docx/d-det.md` 注记 1：检测用子空间距离、**归因才用带符号方向**）；
v0.2 曾做过 r=4 消融（检测口径 rank-1 略优、留作"多方向归因选项"）；P1 探针（`docx/d-det-v0.4.md` 附录）证明
家族方向指纹存在于 Δ 残差（GroupKFold 0.98 可分）。本轮在 SemEval-B 上确认最佳秩 r\*。

### 6.1 冻结特征扫描（`scripts/semeval_r_sweep.py`；v1.0 冻结 h）

**支线 1 — CE 瓶颈**（z=w2_r(h) → 11 类，家族监督）：

| r | 1 | 2 | 4 | 8 | 11 | 16 | 32 | 直连768 |
|---|---|---|---|---|---|---|---|---|
| val F1 | .155 | .283 | .365 | .403 | **.415** | .407 | .402 | .398 |
| test F1 | .120 | .199 | **.273** | .248 | .242 | .228 | .237 | .236 |

→ **低秩有效**：8~11 维到达平台；r≥16 略降；**瓶颈优于全维直连（.415 vs .398）——约束即正则**；
设计区间 4~8 基本命中（峰值延伸到 11=类别数）。

**支线 2 — hinge（设计原案"多模型"版）**：从 B 训练集构造四族真配对（Qwen2.5-Coder-1.5B、Yi-Coder-1.5B、
Llama-3.1-8B、Granite-3.3-8b；共 8 个模型）训练 rank-r 铰链子空间，LR(z) 测归因：

| r | 1 | 4 | 8 | 16 | 32 |
|---|---|---|---|---|---|
| val F1（LR on z） | .073 | .126 | .224 | .248 | **.268**（铰链满足率≈1.0） |

→ 纯偏好铰链子空间**只承载弱家族信息**——**家族信号需家族监督或残差对比**；与 P1 探针一致。
同时回答"v0.2 掉点是否因模型少"：多模型（3→8）也不能救 hinge——主因是铰链目标不含族别信号。

### 6.2 端到端确认（B 微调 + 低秩读出 `--readout-rank`，2ep，与主臂同超参）

| 读出 | val F1 | test F1 | 备注 |
|---|---|---|---|
| 直连头（既有） | **0.5021** | **0.3040** | 满秩头 |
| 瓶颈 r=11 | 0.4029 | 0.2383 | 容量≈直连头（乘积秩上界），仍低 0.10 → 非容量问题 |
| 瓶颈 r=8 | 0.3926 | 0.2546 | |
| 瓶颈 r=4 | 0.3066 | 0.2158 | |

**诊断：冷启动优化受限**——(a) r=11 的乘积头容量与直连头等价，却差 0.10；(b) 三个 run 在 ep1 均未收敛
（train loss 仍在降、val 逐 epoch 升；类 2/Qwen 在瓶颈 run 中完全未学到）；(c) 对照冻结范式（充分收敛后）
瓶颈反而优于直连。原因：row0=w2 + 其余 1e-3 小随机的冷启动 × 2ep × 头 lr 3e-4。
（可选改进：更好的秩初始化/更大头 lr 重试；预算内 1-2 run 可做，暂缓。）

**决策**：B 分数保留直连头；**r\* = 8**（8~11 平台、设计区间顶、维度省）作为 s2 子空间
用于 A/C/B 的特征管线；若后续证据倾向 11 再切换。

### 6.3 下一步（2026-09-25：已完成，方案升级为 §7 六杠杆总攻）

**A/C（及 B 增强）特征管线**：手工特征（R_void/缩进/熵/注释率/行长方差等，取自 `docx/semeval.md` 选手做法）

A 用先验匹配；B/C 在 val 上拟合 stacker + CV。三任务流程各自设计（用户指令）。

- **规模×数据**：Qwen×55K val **.6650**（全项目 B-val 单臂最高）；test .3617 与 1.5B×18K 的 .3777 同带

## 8. 改进方向（2026-09-25 终版后的系统思考）

### 8.1 已实测的低垂果实（含负面结论）

- **per-class 阈值/偏置调优**（`semeval_threshold_tune.py`，零训练，val OOF 坐标上升）：
  B：cv_val .6827→**.6872（+0.45pt）** 但 test **.4196→.4079（−1.2pt）**——val 上调出的
  类权重**不迁移**（test 族极度失衡 + 分布 shift）；C：cv/test 均无变化（权重全 1.0——
  概率已近似校准，无偏置空间可吃）。
  → **结论**：B/C 的后处理空间已穷尽，瓶颈在表征/数据侧；此结果与 §3.6"val 拟合陷阱"
  同源（域内拟合不能外推），再次验证"部署先验不可从 val 偷"。
- **先验重加权**（§7.5）：.4196→.4196，同样无空间。

### 8.2 缺口诊断（瓶颈在哪）

**B（val .683 → test .420，−26pt）**：
- test 1K 的族分布极端（Human 474 / 最大机器族 214 / 其余 8 族 n=10~73）；单臂 per-family
  诊断：Human **.98**、最大族 **.73**，其余 8 族 **.11~.47**——**小族召回是唯一大缺口**。
- by_language：acc .67~.92 与 macro-F1 .28~.43 脱节（Java .28 最弱、Python .39）——
  误差不是"某语言不会"，而是**少数族系统性漏判**（被 Human/大族吸收）。
- 判定：test 与 val/训练在**家族构成与模型版本**上异构（开放集泛化问题），
  不是平衡/偏置问题（8.1 已排除后处理）。

**C（macro .827）**：per-class c0 .96 / c1 .80 / **c2(Hybrid) .71 / c3(Adversarial) .77**——
最弱两类恰是"人机混合"与"RLHF 伪装"，即理论上与 s2（偏好位移）/R_void 最相关的两类；
说明二轴特征在 C 上的**利用仍不充分**（当前只是把 probs 丢给 LightGBM，没有专门驱动）。

### 8.5 内核 mini 实验（E1/E2/E5/E6，2026-09-25；详见 `docx/d-det.md` §3/§6/注记 1 修订）

用真实 $r^*=\log p_i-\log p_b$（双模型打分）拷问 s2 理论，四个 mini 实验（共 ~2h GPU）：
- **E1**（Qwen1.5B 对，200 条）：免训练检测 AUC **0.81**；人→base→instruct 单调梯度（p=8e-9）；
  族间结构 p=0.003；学习的 s2 与 $r^*$ 反号（−0.25）。
- **E2**（hinge vs BT × 0.5B/1.5B 监督）：与 $r^*$ 相关性四组一致 ≈ −0.23——**损失形式/监督源均非瓶颈**。
- **E5**（DeepSeek 对）：跨模型对 $r^*$ 互相关仅 0.13（检测 AUC 反号 0.42）——"跨实验室稳定"证伪。
- **E6**（+0.5B 对，3 维拼接）：同实验室 0.5B↔1.5B 相关 0.51 > 跨实验室 0.13；**$r^*$ 读数群 + s1
  融合检测 AUC 0.73 → 0.86（互补显著）**；细粒度族归因需监督读出（NCM ≈ 随机）。
⇒ 启示：**"位移读数群"是继 s1 之后的第二类弱监督/免训练信号**（与 A 任务 rvoid 融合同型）。

**A×Qwen 收尾（同日，`semeval_qwen_probe.py` + `semeval_a_fusion3.py`）**：
- Qwen1.5B 微调 A：val .9898 / **test .2777（崩，比 CodeT5 的 .3955 更甚）**——"微调摧毁跨域"第二例，
  且此例中模型在 test 上几乎全判 machine（human 召回 .093）——**普遍规律，非骨干偶然**。
- 冻结探针（原始底座 + LR）：prior22 **.6428**（弱于 CodeT5 冻结 s1 的 .7086，但方向可用）。
- **融合（prior22 协议）**：复现旧版 0.7·s1+0.3·rvoid = **.7492**（口径核对 ✓）；
  **等权三源（s1+rvoid+Qwen 探针）/3 = .7811（新最佳，+3.2pt，零选权零泄漏）**；秩和 .7637；
  val 选权→纯 Qwen 探针→test 崩 .6428（**val 拟合陷阱第 3 例**）；test 探索上界 .7869。
- 结论：A 的融合权重**必须无监督**（等权/秩和）；"读数群"互补在 A 上定性复现（E6 同型）；
  Qwen 探针单独弱但组合增益大——多样性来源比单体强度更重要。
