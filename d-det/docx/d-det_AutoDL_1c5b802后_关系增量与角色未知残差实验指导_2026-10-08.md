## 2. 实验 A：端点边际平衡的关系增量

### 2.1 直接可用的构造脚本

服务器只需该脚本/小型 plan 及既有 `metrics_f0b_fix.json`，不需原件 bundle。服务器复建命令：

```bash

  --members-json d-det/artifacts/f0_series_member_holdout_fix_2026-10-08/metrics_f0b_fix.json \
  --out d-det/artifacts/endpoint_balanced_relation_plan_2026-10-08
```

这个 plan 是协议模板，展开到既有 train/dev tasks 时才生成特征行。不要将 48 折视为 48 个独立样本。

### 2.2 标签定义修正

标签严格为 `same_observed_series`：**任意**同系列对都为正类，跨系列对才为负类。旧实现给 `others` 内所有组合标负，其中包含另一个系列内的同系列对；它对应的是“是否来自当前目标系列”，不是通用 same-series relation。旧数字保留为 target-series-conditioned diagnostic。

新实验同时留出每个系列一个成员，记为 \(h_s\)，训练成员为 \(M_s\)，数量 \(n_s\in\{2,3\}\)。覆盖所有 \(4\times4\times3=48\) 组合，顺序由脚本冻结。

### 2.3 训练权重

每个任务完整使用所有训练成员内/跨系列对。无序正对 \((a,b)\subset M_s\) 的权重：

\[
w^+_{ab}=\frac{1}{3\binom{n_s}{2}}.
\]

跨系列负对 \(a\in M_s,b\in M_r,s\ne r\) 的权重：

\[
w^-_{ab}=\frac{1}{3n_sn_r}.
\]

每类总权重为 1；每个成员在两类中的端点权重都是 \(2/(3n_s)\)。因此不能凭单个训练端点的标签频率解题。展开 task 后除以该 split 的 task 数；训练 sample weight 再统一缩放至均值 1，以免无意改变正则强度。

### 2.4 评测权重

正对为 \((h_s,b)\), \(b\in M_s\)，权重：

\[
w^+_{h_sb}=\frac{1}{3n_s}.
\]

负对为 \((h_s,b)\), \(b\in M_r,r\ne s\)，权重：

\[
w^-_{h_sb}=\frac{1}{6n_r}.
\]

每个 anchor 的正/负权重都是 \(1/3\)。对于任意 partner \(b\in M_r\)，正类权重 \(1/(3n_r)\) 等于两个其他 anchor 的负类权重和。故任意只依赖 anchor 或只依赖 partner 的分数，在该加权评测总体上应恰为 AUROC 0.5。

该权重定义了**系列平衡的标准化评测总体**，不是自然样本比例。主报告 weighted AUROC/AP；unweighted 另列敏感性。保持所有 pair，不通过挑短代码或最优成员来删样本。

正反方向训练各半权重，推理用双向平均。或者直接使用 `[abs(u_i-u_j);u_i*u_j]` 的对称接口。不得以 canonical 排序本身建立“顺序泄漏已排除”的结论。

### 2.5 五个有科学区分力的读出

1. **Endpoint-only**：anchor-only、partner-only（不用训练 heldout h 的 train 行；仅评测其已有分数即可检查构造）。加权 AUROC 应为 0.5，否则构造失败，不跑剩余模型。
2. **Independent-source composition**：在训练成员的 train tasks 上训练三系列分类器 \(p(f\mid u)\)，关系分数固定为
   \[
   s_{compose}(i,j)=\sum_{f=1}^3p(f\mid u_i)p(f\mid u_j).
   \]
   不在 dev 对上拟合组合器，不读取 heldout h 的 train 代码。
3. **Symmetric relation**：`q_sym=[abs(u_i-u_j);u_i*u_j]`，加权 LR；与旧 q 双向平均并列。明确 feature scaler 只用 fit fold。
4. **Strong P0 relation**：完整双侧 lexical/style 视图的独立系列分类器组合，以及同样对称 pair 特征的 LR/LGBM。保留现有强 P0 的融合/equal 控制；未实现完整 P0 时标 partial，不能称已经超过它。
5. **Relation residual**：冻结 composed baseline 后仅训练一项有界残差
   \[
   \ell(i,j)=\operatorname{logit}\!\bigl(\operatorname{clip}(s_{compose},\epsilon,1-\epsilon)\bigr)
            +\gamma r_\phi(q_{sym}),\qquad\gamma_0=0.
   \]
   使用固定单层/小 MLP，不叠加 SupCon、QDA、正交等。重点是增量，残差失败照实归档。

先在冻结顺序的首折做 pipeline smoke、端点边际和角色排除断言，再完成 48 折。超参数只在 train tasks 内的内层 split 选择；dev 171 是外层开发评测集。固定 seeds `[0,1,2]`，同时设置 numpy/torch/cuda 初始化 seed。记录每模型实际参数量、训练步数、收敛/损失，不靠不收敛的 P0 凸显方法。

### 2.6 主比较和出口

主增量：`relation_residual − independent_source_composition` 和 `relation_residual − strong_P0`。对称 q、单侧、双侧均按相同 weighted 指标比较。

48 折共享 tasks 且共享训练成员，**禁止**对 48 个折 AUROC 做 iid t-test。主 CI 用共享 task-cluster bootstrap：每次所有折使用同一个有放回 task 序列，各折重算加权指标后按冻结平均汇总。报告适用边界：CI 条件于当前有限成员集合，不代表所有新模型。成员/系列差异单列描述性统计，不伪装成增加有效样本量。

20 次以上置换作为实现 sanity，仅跑冻结的代表折；同一 unordered pair 的所有 task 行和两个方向用同一置换标签。主证据是与 composed baseline 的**配对差值 CI**，不是“真实 AUC 高于置换”。置换 p 值采用 \((1+\#\{T_b\ge T_{obs}\})/(B+1)\)，20 次置换最多支持约 1/21 的分辨率；100 percentile 不等于 p=0。方向不能用评测标签选择 `max(AUC,1-AUC)`。

- 若端点平衡失效：修复构造，不解释模型。
- 若 q/residual 不能超过 composed baseline：记录“现有观测关系可由来源分类组合解释，未见额外关系增量”，保留 F0-B 来源可读性。
- 若增量同向且共享 task CI 下界大于 0，才称**当前三个已知系列中的关系增量开发证据**；下一步用新任务确认。
- S-HO 阴性边界不消失，不能据此写普遍家族几何。

## 3. 实验 B：角色未知的 S-resid

现有 `ctrl_mat` 使用 `style[Ri]`，Ri 是已知 instruct 行。回归虽然只在 fit fold 拟合，但 `S_resid=S-C_instruct B` 在评测时仍依赖真实角色；同一个残差被放进 `[S_resid;±A]` 两个方向。这是 oracle-conditioned 接口，不能直接作为“辨认哪一侧是 instruct”的部署表示。

### 3.1 角色未知预处理

输入只有一对未排序代码 `(x1,x2)`。每侧都可计算自己的 C，构造交换不变控制：

\[
C_{sym}=[(C_1+C_2)/2;|C_1-C_2|;C_1\odot C_2].
\]

回归 \(S\sim C_{sym}\) 只在 fit fold 估计（内层 cross-fit/ridge）。角色未知残差

\[
R=S-\widehat S(C_{sym})
\]

必须满足输入交换时 `R(x1,x2)=R(x2,x1)`，而 A 变号。方向分数

\[
d=g(R,A)-g(R,-A)
\]

应严格变号，不用真实 mode 选择控制侧、做方向校准或挑样本。监督标签只进入训练 loss 和最终指标，不进入特征构造。

并列三臂：A-only、raw S+A、role-blind R+A；旧 oracle 视图仅作上界。记录 fit-only 标准化、ridge/白化的实际应用；目前 `core_sresid_precheck.py` 返回 mu/sd，但 out/eval views 未使用它们，不能把“算过统计量”写成“执行了标准化”。旧 scale_audit 的 std 实验单独保留。

必须先跑随机50%翻转原始输入、角色名重编码、特征交换不变性断言，再跑相同 task/model folds，3 seeds。明确 A-only 与 `[R;A]` input dim 不同造成参数量差异，用 `[0;A]` 做匹配容量版本。禁止在训练 endpoint probe 时读取 heldout h 的 train 行；旧 `hX_tr=U[(h,t)]` 仅是无用的常数探针，也应从数据访问声明中纠正。

如果 role-blind 增量消失：归档为 role-assisted/oracle-conditioned phenomenon。若保持：作为真实后训练候选 R1 的输入接口；仍是协议条件研究，不能把 complete/instruct 冒充 checkpoint 后训练差异。

## 4. R1 checkpoint 对照与 H3

### 4.1 R1 正反配对核对（与实验 A/B 同轮）

此前 `core_r1_edges.py` 用 `[S;D]` 和 `-[S;D]` 构造正负。真正交换 child/base 只应改变 D，不应改变 S：

\[
[S;D]\longleftrightarrow[S;-D].
\]

先逐项查看后续 `core_r1_update.py` 是否沿用该错误；若沿用，将旧近1.0的 SD 数字标成 sign-construction diagnostic，并用正确交换接口重跑 7 边的 train/dev（模式分开，未知role预处理），不要重复宣传完美识别。

R1 是真实 child/parent 候选 checkpoint 的观察性对照；它不依赖 F2 的 gate 才能做。边图区分直接 parent 与祖先、共享 parent 的相关性，版本/训练关系仍 partial。写清每条边更接近 SFT、蒸馏、进一步预训练或 unknown；不能统称纯 SFT/DPO 因果。以正确 Delta/联合/完整 P0、endpoint组成、edge-heldout 比较为本轮方法证据。

### 4.2 H3 的定义恢复

H3 原定义为 Human/AI detection 与来源归因的任务分离。当前 BCC 两种 mode 都是 AI，代码中 D 只是协议方向。因此：

- 对已完成四配置做记录收尾，保留开发诊断，不重跑补满 epoch；
- 从真实 human/AI 数据构建支持表：task/prompt对应、human来源与许可证、语言、split、AI unit；
- CodeContests human 与 BCC AI 不是同题，不能直接拼接并称“检测轴与归因轴分离”；
- 没有合规 human 支持时报告 `H3_original_unavailable`，不把 D 改成协议方向来满足 gate。

共享编码器 H3 后续报告梯度余弦的完整分布、负余弦干扰率、惩罚激活率、检测非劣界限和归因配对CI。原 `relu(cos-0.3)` 惩罚正对齐，未必等于减少负梯度冲突；理论目的需在正式协议前明确，不能通过调阈值强行激活展示收益。
