# E36 后续指导：最终审计与 H2 收尾

## 结论先行

E36 已经完成了 DroidCollection 子集上的预注册 H2 候选检验：

- fold 0：F1−F0 = `+0.14 / +0.06pt`；
- fold 1：F1−F0 = `−0.28 / −0.37pt`；
- pooled：`−0.17 / −0.20pt`；
- anchor 守卫通过：`.714 / .857`；
- held-out family attribution 的 BA_F 约 `.16`，接近机会水平 `.1429`。

因此，不再启动 E37 模型变体，不再调 SupCon、门控、学习率、温度、训练轮数或几何损失。DroidCollection 的价值是揭示：当前冻结 768 维表示在跨 generator 条件下家族来源可读性很低；它不是继续堆叠损失的理由。

E36 的主结论可以冻结为：

> 在 DroidCollection 子集和当前冻结表示下，跨 generator 关系约束没有带来稳定的 family attribution 增益；结果不支持实用 H2。

表述必须限定为 DroidCollection 子集与当前表示，不能写成 H2 在所有数据上已经被证明或证伪。

## 一、先修两个审计问题

### 1. 修正运行 provenance

当前 `artifacts/h2_droid_e36/manifest.json` 的 `commit` 是 `ac12744`，但 E36 脚本和产物后来才在 `2cc9695` 提交。特征缓存可以复用，因为它由相同冻结模型生成；但最终报告必须能从当前提交复现。

在 AutoDL 当前仓库 `/root/autodl-tmp/u-det/d-det` 执行：

```bash
source /etc/network_turbo
OMP_NUM_THREADS=8 python scripts/h2_droid_e36.py \
  --out artifacts/h2_droid_e36_repro \
  --force
```

要求：

- 新 manifest 的 `commit` 必须是当前 HEAD；
- `core.jsonl`、`fold_plan.json`、特征缓存 hash 不变；
- 两折和 pooled 的 B0/F0/F1 指标与原 E36 一致，允许只有浮点显示差异；
- 把 `h2_droid_e36_repro/metrics.json` 与旧产物逐项比较，输出一份 `repro_compare.json`；
- 如果结果不一致，停止，不要调参，报告差异来源。

复现核对完成后，再决定是否把 repro 产物替换为正式 `h2_droid_e36`。不要删除旧产物，直到逐项比较完成。

### 2. 修正随机参照的 test 使用声明

当前 `run_fold()` 的随机参照从全部 machine 行构造随机切分，因此可能把原始 `split_source=test` 行放入随机参照训练侧。它没有污染 H2 的 B0/F0/F1 held-out test 结果，但与 manifest 中的：

```json
"test_used_for_final_eval_only": true
```

不完全一致，也会让随机参照偏乐观。

处理方式二选一，优先 A：

**A（推荐）**：修改随机参照，只使用原始 `split_source=train` 与 `split_source=dev` 的 machine 行构造随机训练/参照评估；明确随机参照只用于描述迁移损失，不进入 H2 出口。重新运行并在报告中说明新口径。

**B**：如果不想改代码，就删除报告中“随机参照约 `.29-.31`”的定量迁移损失解释，改成“现有随机参照仅为探索性诊断，可能含原始 test 行，不作为证据”。同时把 manifest 的 test 使用声明改为准确描述。

不要把随机参照修正后的变化误报为 H2 方法结果变化。主实验结论只由 held-out test 上的 B0/F0/F1 决定。

## 二、最终代码审计

只做实现核对，不做性能搜索：

1. `fold_plan.json` 的 train/held-out generator 交集仍为 0；
2. `source_row_sha1` 跨 split 和 split 内重复仍为 0；
3. test generator 没有参与 B0/F0/F1 的拟合、标准化统计量、early stopping 或超参数选择；
4. diagnostic 文件没有进入训练、特征拟合或评分；
5. F0/F1 共享初始参数、随机种子、batch schedule、标准化和 optimizer；
6. 初始化时 F0/F1 logits 与 B0 逐位一致；
7. 跨 generator 正对只允许同 family、不同 generator；
8. `BA_G` 是 held-out generator 分组后的 family recall 平均，不能被写成 unseen generator 分类准确率；
9. 记录 `codet5-base`、冻结 checkpoint、tokenizer、max length、batch size 和特征 hash；
10. 只保留一份正式 E36 产物，避免 smoke、pre-commit 和 repro 结果混入论文表格。

## 三、报告收窄方式

E36 报告保留以下结果：

- 主指标表：B0/F0/F1 两折和 pooled BA_F/BA_G；
- anchor 覆盖率；
- 每个 held-out generator 的 family recall；
- Droid 子集上接近机会水平的跨 generator attribution；
- 与 E35 的严格分开比较。

报告删除或降级以下内容：

- 把随机参照的约 13pt 差距写成主证据；
- 把检测 AUROC 当作 H2 支持证据；
- 把单个 family 或 generator 的正增益写成总体改善；
- 把 DroidCollection 结果外推到 task-level 或 prompt-invariant 结论。

推荐最终论文表述：

> 在 DroidCollection 子集上，family attribution 在 generator-held-out 条件下接近机会水平；加入仅跨 generator 正对的残差约束后，两折增量方向不一致，pooled BA_F/BA_G 分别下降 0.17/0.20 个百分点。因此，在当前 768 维冻结表示和该数据构型下，没有观察到稳定的 H2 增益。该结果是数据构型和表示条件下的阴性证据，不等价于对所有 task-aware 数据上的 H2 作普遍否定。

## 四、后续工作边界

E36 收尾后，下一步不再是新的模型实验，而是：
