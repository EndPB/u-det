## 0. 这份文档要解决什么

过去的工作已经给出了许多有价值的负结果和数据边界，但研究问题逐渐被几个近似混在一起：Human/AI 检测、AI 内部生成器或家族识别、四类创建方式判别、代码格式捷径、以及“后训练差异”的机制解释。接下来需要先把它们重新放在一个能被证伪的观察模型中，再决定数据和模型。

这份讨论稿不撤销任何历史结果。C0–C3 的关闭、H3 frozen CodeT5-small 诊断的关闭、各轮 H3 闸门为 `revise_data`、长度和词法 probe 偏高、AMMC 目前未产生稳定增量，全部作为后文的已知证据。它们限制的是旧设计能够声称什么，不限制重新设计一个更干净的主线。

本稿也不把“后训练差异”直接写成已经识别的因果变量。若没有相同 base、相同任务、相同采样和可追溯训练过程，模型输出只能支持“与 post-training 相关的可观测差异”或“来源/策略差异下的预测信号”。真正的因果归因需要另行收集受控模型谱系。

## 0.1 ACL 论文必须先固定一个核心卖点

上一版把核心退成“内容—布局融合和跨分布验证”，这不够接近 d-det 真正要回答的问题。本稿恢复中心问题：**基于代码条件的后训练差异（Code-Conditioned Post-Training Differences）**。

> **研究假设：不同后训练策略会对代码实现、组织和呈现施加不同的选择偏好。对于同一段待测代码，这些策略相对参考策略的偏好变化可以形成一个多维差异表示；该表示是否能在基座和任务变化时迁移，并帮助检测与含 Human 的家族归因，是 d-det 的核心问题。**

“代码条件”有两个层次。机制理想式是在同一段 c 上比较不同政策的相对评分；旗舰主轨道无法访问这些内部评分，因此用同一 task/接口下各来源生成的代码样本估计相对输出分布，再把同一 parent 的安全变体作为响应测试。它不是先收集一段 Human 代码和一段 AI 代码相减，也不是把 task ID 拼进分类器。任务描述 t 是生成分布的条件，代码 c 是观测对象，二者不能混用。默认部署只输入待测代码，不要求同题 Human/base 样本、测试任务原型或元学习支持集。

候选论文标题：`d-det: Code-Conditioned Post-Training Differences for Code Detection and Human-Inclusive Attribution`。这是待验证的方法定位，不宣称创新优先权或已完成的结果。

核心贡献不能依赖旗舰模型可获得内部谱系这一事实上不存在的前提。论文应区分两条证据轨道：主轨道从多个最终模型/agent 的可重复代码输出学习**代码条件的相对行为差异**，并检验它对 A/C 检测与含 Human 的 B 家族归因是否有增量；机制副轨道只在能拿到公开 checkpoint 谱系的模型上验证这些差异是否与受控后训练变化相符。格式是让代码条件差异不被 tokenizer/汇聚过程遮蔽的观测通道；AMMC 是检验捷径依赖的训练和评估工具；长短代码、formatter 和来源外推是验证条件。它们服务于中心假设，不能替代它。

主线采用一个明确的工作假设：旗舰模型的有效 base 行为差异相对其后训练/agent 行为差异可忽略，即主线设计中令 \(\epsilon_{fg}(t,c)\approx0\)。这是为了快速检验“基于代码条件的后训练差异”线路，不是声称已经完成因果识别；若主结果成立，再用少量可得谱系或 base/tokenizer 控制做后补敏感性分析。对于闭源旗舰，默认拿不到预训练 base、SFT/RL checkpoint、训练数据和完整运行历史，因而主实验不要求 base→post 配对。公开 checkpoint 谱系只作为后补机制校验，不阻塞主线。

### 核心主张的三个可证伪预测

1. **代码条件差异：** 在相同 task、接口、长度桶和采样预算下，模型/agent 来源之间的相对输出行为仍能从代码本身预测；打乱来源标签、只保留 project/length 统计或只保留单一词法视图后，该增量应显著收缩。
2. **跨来源迁移：** 在未参与训练的模型、agent runtime、任务和 formatter 上，差异表示仍能改善 A/C；主线暂按 \(\epsilon_{fg}\approx0\) 解释为后训练/运行策略差异，base/tokenizer 敏感性作为后补实验。如果只识别某个项目或输出模板，则收缩为来源专属探针。
3. **可得谱系校验：** 在少量拥有 base→post 或 post→post checkpoint 的开放模型上，作为后补检查黑盒差异与同谱系 log-ratio 的方向和代码分层趋势是否相符；这一项不进入旗舰主线的启动门槛。

这些预测不要求闭源旗舰提供训练数据。它们要求的是模型输出的版本、接口、采样配置和代码/任务 provenance 可复现。
若只有格式融合有效、差异监督无效，应如实报告格式模块的收益并否定本次后训练差异实例化，不能把普通分类收益重新命名为后训练证据。历史 C0–C3 和 H3 负结果继续保留，不按新叙事改写。

## 1. 重新确定三个目标

SemEval-2026 的 ABC 任务只作为问题形状的参照，不是本项目必须复刻的标签协议。d-det 的目标应明确为：

* **A：二分类检测。** 给定代码和可选的任务上下文，判断 Human 或 Machine。主问题是相对于完整 CodeT5 微调基线，代码条件、格式通道和训练变体能否提升跨任务、跨语言、短长代码和外部格式化后的稳健性。
* **B：含 Human 的家族归因。** 类别包含 Human 以及若干 AI family/source unit。它回答“这段代码更像哪个创建家族”，不是只在 AI 行中做 generator 分类。AI-only source 预测仍可作为诊断，但不能代替正式 B。
* **C：四分类检测。** 四个类按本项目已构建数据及实际标签协议核实，字母 C 本身不规定四类名称；不能自动移植 SemEval/AICD 的四类定义，也不能因数据缺口擅自把研究目标改为更少类别。

A、B、C 共享代码编码器，但不共享“标签含义”。B 中 Human 是一个真实类，不能靠把 Human 行排除来制造所谓 family head；C 需要创建历史或严格的构造协议，不能由普通格式变体事后贴上 Hybrid/Adversarial 标签。

## 3. 核心数学对象：同一代码上的多政策后训练差异

### 3.1 两种可区分的数学对象

先写理想化的机制对象。若同一 base 谱系 b 的 reference policy 为 p_{b,0}，某个后训练处理 k 的 policy 为 p_{b,k}，KL 正则奖励优化给出

\[
p_{b,k}(c\mid t)=\frac{p_{b,0}(c\mid t)\exp u_{b,k}(t,c)}{Z_{b,k}(t)},\qquad
\log\frac{p_{b,k}}{p_{b,0}}=u_{b,k}-\log Z_{b,k}.
\]

该关系是 DPO/RLHF 的理想化解释，见 [DPO §4 与附录 A.1](https://arxiv.org/html/2305.18290v3)，不是对真实旗舰训练流程的观测事实。只有当 b、阶段和条件可追溯时，\(u_{b,k}\) 才能被称为受控后训练变化。

旗舰主轨道使用可观测的黑盒行为对象。对最终模型或 agent 来源 f、g，定义在固定 task 接口、采样协议和代码表示下的输出分布：

\[
r_{fg}(c\mid t)=\log\frac{p_f(c\mid t)}{p_g(c\mid t)}.
\]

若把每个最终 policy 写成未知 base 行为与行为改变量的组合，

\[
\log\frac{p_f(c\mid t)}{p_g(c\mid t)}=\underbrace{\log\frac{p_{0,f}(c\mid t)}{p_{0,g}(c\mid t)}}_{\epsilon_{fg}(t,c)}+u_f(t,c)-u_g(t,c)-\log Z_f(t)+\log Z_g(t).
\]

\(r_{fg}\) 是可估计的相对行为差异；\(u_f-u_g\) 才是我们希望讨论的后训练部分，而它不能在没有 base/训练历史时从\(r_{fg}\)唯一识别。主线把 \(\epsilon_{fg}\approx0\) 作为可证伪的工作近似，以便快速检验线路；它不是从最终输出中证明出来的定理。若后补敏感性分析显示基座/Tokenizer 残差很大，就把结论收缩为最终来源行为差异。

若有同一 base 的两个后训练处理，代码配对差分可以消除部分 task 归一化项；但这只适用于可追溯谱系的机制副轨道，不是旗舰主轨道的必要输入。没有这种谱系时，不构造虚假的\(L_{\rm diff}\)标签，也不把 Human/AI 两侧命名为 post/reference。

### 3.2 黑盒差异怎样学习，以及它不是什么

给定来自最终来源 f 的可追溯输出样本和匹配的来源 g 样本，在同一 task、语言、长度桶、接口和采样先验下训练来源判别器。其最优 logit 是

\[
a^*_{fg}(c\mid t)=\log\frac{p_f(c\mid t)}{p_g(c\mid t)}+\log\frac{\pi_f}{\pi_g}.
\]

因此必须匹配或校正来源先验；这只是密度比估计的统计事实，不是把普通 source classifier 改名为新方法。若没有 task 条件，代码单输入模型学习的是混合分布密度比，不应写成某个固定 t 下的条件 log-ratio。

方法贡献必须来自**如何把这些相对行为差异变成代码条件表征并验证其迁移**，而不是来自一个来源 CE。候选表征可由成对 logit、跨任务/跨 formatter 的差分响应，以及同一 parent 的安全格式/语义变体响应组成：

\[
\Delta_{fg,T}(c)=a_{fg}(c)-a_{fg}(T(c)).
\]

\(T\) 是预注册且通过 CST/编译安全审计的代码变换。\(\Delta\) 是最终模型行为对代码条件的响应，不等于 post-training reward；它提供一个比单点来源 logit 更具体的“代码条件”检验。训练时要同时对照 shuffled-source、shuffled-transform、layout-only、lexical-only 和同预算 CodeT5，避免把标签泄漏或增强标记当成差异。

主轨道不要求调用旗舰模型的 token log-prob。若 API 可提供 log-prob，可把它用于小规模校准；否则从版本化输出样本估计密度比。模型输出必须记录 checkpoint/model release、prompt、temperature、工具链、formatter、失败重试和时间窗口。缺少这些记录的样本仍可进入普通 A/B/C 外部测试，但不能进入代码条件差异主监督。

这里不能偷换一个关键事实：闭源 API 通常只给一次或少量最终代码，不给同一个 c 在两个 policy 下的 log-prob。因此 `a_fg(c)` 是由来源条件样本集合学习的密度比函数，不是“把旗舰模型当作打分器逐段询问”。若只有一份不可复现的输出，最多做外部 A/B/C 测试，不能训练代码条件差异表征。

### 3.3 旗舰 agent 差异要分成训练与运行两个因素

后训练改变政策；工具接口、测试反馈、编辑预算和 formatter 改变政策所处的运行条件。同一 checkpoint 的 direct/agent 对照测量运行流程效应，不直接测量后训练。对可控数据分别比较：固定运行框架改变 checkpoint；固定 checkpoint 改变运行框架；有条件时再测两者交互。

最终文件是交互轨迹边缘化后的结果。部署不用工具日志或隐藏推理；只研究这些过程能否在最终代码上留下可迁移差异。若仅发现 agent runtime 效应，论文应按运行流程差异报告，而不是归因给 RL/SFT。

### 3.4 内容与布局观测模型

令 `t` 是任务，`u` 是代码的语义/结构内容，`l` 是呈现布局，`c` 是实际字符序列。用一个语言感知的解析和渲染关系表示：

\[
c = R(u,l),\qquad b(c)= (u(c),l(c)).
\]

这里的 `l` 不只包含缩进宽度，还包括 tab/space 模式、混合缩进、空行、行尾空格、行长分布、换行风格、注释位置和可被安全解析的呈现信息。字符串字面量、Python 有意义的缩进、宏和正则中的空白不能被无条件归入“无害布局”。实际实现应保存 lexer/CST 的安全边界，不能把 AST 相同当作语义完全相同。

对一个已知来源/策略条件 `q`，把代码分布写成：

\[
p(c\mid t,q)=p(u\mid t,q)\,p(l\mid u,t,q).
\]

`q` 是观测到的创建条件集合，例如 Human、模型 family、具体 checkpoint、agent runtime、prompt 模板、工具链和 formatter。它不是一个可直接从黑盒输出中唯一恢复的“后训练坐标”。对两个来源 `q_1,q_2`，可计算：

\[
\Delta_{12}(c\mid t)=
\log\frac{p(c\mid t,q_1)}{p(c\mid t,q_2)}
=\log\frac{p(u\mid t,q_1)}{p(u\mid t,q_2)}
+\log\frac{p(l\mid u,t,q_1)}{p(l\mid u,t,q_2)}.
\]

这个等式是行为分解，不是因果识别。除非 base、采样、任务和环境都被受控，否则第一项和第二项都可能混合 base、能力、prompt 和 post-training。研究上仍然有价值，因为 A/B/C 正是要预测这种来源相关的联合痕迹；论文要把“predictive attribution”与“causal post-training effect”分开。

### 3.5 下游标签和预测分布

令 `y_A∈{Human,Machine}`，`y_B∈{Human,f_1,…,f_K}`，`y_C` 是四类创建方式。编码器输出三类互补表征：

\[
z_s=E_s(c,t),\qquad z_l=E_l(c,b(c)),\qquad
z_x=G(z_s,z_l),\qquad a(c)=A_\phi(z_x).
\]

`a(c)` 是 K 个可观测来源之间的相对行为差异估计，不是 Human/AI 标签；只有公开谱系副轨道才把其中一部分解释为 post-training delta。下游任务分别比较：

\[
p_r(y\mid c)=\operatorname{softmax}\big(W_r a(c)+U_r z_x+b_r\big),\quad r\in\{A,B,C\}.
\]

必须同时报告 `z_x`-only、`a`-only 和 joint 三个读出。只有 joint 超过 `z_x`-only 且 `a`-only 在谱系/基座外推上保留增量，才可以说差异表示贡献了信息；若只 `z_x`-only 有效，中心假设没有被支持。Human 类由真实人类代码监督，不把 Human 当成某个 post-training reference。

`z_s` 负责代码的语义和结构，`z_l` 负责可观察布局，`z_x` 允许任务头使用二者的交互。没有理由要求 `z_s` 和 `z_l` 在统计上完全独立；真实生成过程可能正是“模型的结构选择和格式选择相互作用”。强行把所有信息分成两个正交桶，会重演旧 H3 中没有证据支持的 disentanglement 假设。无监督 disentanglement 在没有归纳偏置和监督时本来就不可识别，Locatello 等人的研究应被当作警告，而不是再加一个抽象分离损失。

## 3.6 本机初测：黑盒差异可做，机制监督不能凭空补造

本机完成了三个低成本检查，均不训练论文模型、不下载权重。现有数据的缺口应精确表述为“没有已登记的谱系字段”。主线不等待该字段，而是优先利用已存在的百千级最终输出；缺失谱系只限制后补机制解释：

1. `scripts/audit_acl_local_readiness.py` 流式审计八类现有数据，共 266,825 行。`base_model` 和 `model_role` 字段在这些包中缺失；STACAD alignment 仍适合 Human/AI task 对齐，但不能直接提供 base→post 的机制标签。审计产物位于 `d-det/artifacts/posttraining_difference_local_feasibility_2026-10-12_run1/`。
2. `scripts/posttraining_difference_formula_sanity_2026_10_12.py` 在合成高斯政策上验证了密度比判别的统计性质：平衡先验 RMSE `.0268`；3:1 采样不校正 RMSE `1.0896`，校正后 `.0101`；跨基座 post-vs-post 只能恢复混合差异，针对预设 within-lineage delta 的 RMSE `.5283`。这支持“黑盒相对行为可估计、纯 post-training 不可自动识别”，不是论文效果结果。
3. `scripts/posttraining_difference_candidate_scan_2026_10_12.py` 扫描 `public_same_task_full` 的 296,254 行，发现 131,100 个同模型同 task 的 `complete/instruct` 模式配对代码哈希相同。该结果只能说明当前包中的模式对比不能当作处理标签；`generation_mode` 也不是后训练谱系。它不证明旗舰模型没有可追溯数据。当前记录的 `code_sha256` 与 `code` 字段一致性仍应在后续数据入口单独复核。

因此当前正确决策是：

* 旗舰主轨道：用多来源最终输出学习 `r_fg` 和 `Delta_fg,T`，做 A/B/C 的增量、鲁棒性和长短代码主表；
* 机制副轨道：若找到公开且可验证的 base→post/post→post checkpoint，再训练/校准同一差异表征，检查方向一致性；找不到则不阻塞主轨道；
* 任何来源、模式或目录字段都不能直接改名为 `L_diff`。


## 3.7 数据规模裁定与快速 pilot 的地位

16,768 行 STACAD 对齐池只适合检查脚本和线路，不能承担 d-det 主表。当前已盘点到两个可扩展入口：

* `d-det/data/public_same_task_full_2026-10-07/records.jsonl`：296,254 行、1,539 个任务，包含多模型/多发布版本和 complete/instruct 等协议字段；这些字段必须先做角色审计，不能直接把 `generation_mode` 当 post-training 标签；
* STACAD-v2 清洗摘要：144,958 个保留代码 pair、22,053 个文件、七种语言，适合大规模 Human/AI 与多来源检测控制，但应按 task/file provenance 重建 split。

规模目标是扩展有任务/来源证据的内部数据，优先利用完整 STACAD、已有同题数据和已构造变体；报告独立 parent、任务、generator、family 和增强视图数，不能以增强后的行数冒充独立样本数。100k+ 规模方向保留，16k 小池不作为最终主表规模。AICD 只有 code/label 的公开包保留为外部数值控制，不因行数更多而替代任务中心化、语义分离或项目 ABC 标签。某个子任务的规模或标签尚不满足时应如实登记缺口，不能改换研究目标。

本机已完成的 `blackbox_code_response_local.py` 小池线路试跑使用 16,768 行和 CPU TF-IDF 来源分数，三 seed 的八类 B macro-F1 约 `.314-.328`（直接多视图 CodeT5 外的轻量对照约 `.335-.350`）；response-only 没有增量。这只证明当前轻量 response 定义需要在大池和真正 CodeT5 主模型上重测，不是主线结论。结果目录 `d-det/artifacts/blackbox_code_response_2026-10-12/` 保留为 pilot，主线不据此停线。


## 4. 推荐的模型主线

### 4.1 基线必须升级为真正可比的 CodeT5 微调

主表的第一列固定为完整 CodeT5 微调：相同最大长度、相同滑窗/长代码处理、相同 train/dev split、相同 seed 集合和参数预算。旧的 frozen encoder + 小头结果继续保留为历史诊断，但不能作为新方法的唯一对照。

### 4.2 一个格式通道，而不是手工特征堆叠

建议使用“代码 token 流 + 行/布局流 + 对齐交互”的单一编码器变体：

1. 代码 token 保持 CodeT5 的预训练表示；
2. 对每个 token 或行附加 lossless layout 标记：原始 tab 数、space 数、换行类型、行首/行尾空白、行号、行长和局部行统计；
3. 用轻量 line/layout encoder 得到 `h_l`，通过 token-to-line 对齐或 cross-attention 与 `h_s` 交互；
4. 对超长代码使用分层 pooling 或窗口级 attention，不能只取头尾平均；
5. 另保留一个“纯手工统计 + 线性模型”控制，证明提升来自学习到的代码条件交互，而不是把长度列拼接进去。

格式通道应能看到 tab、2/4 space、混合缩进、空行率、行尾空格数量和行长方差。tokenizer 是否区分这些字节只回答输入信息是否可恢复；格式通道实验回答模型是否从它们获得泛化增量。`trailing_ws` 这类单项可能与标签反相关，不能预设方向。

### 4.3 选择性鲁棒性，而不是全局不变性

对安全的呈现变换 `T_l`，A 的检测头应在格式化前后大体稳定；但 B 可能恰恰需要利用稳定的 family style，C 的 Hybrid/Adversarial 也可能具有真实格式证据。因此不对整个 `z_x` 施加无条件不变性，只在预先指定的 head 和变换集合上施加有限一致性：

\[
L_{\mathrm{view}}=
\mathbb E_{(c,T_l(c))}
\left[\mathrm{JS}\big(p_A(c),p_A(T_l(c))\big)
+\rho\,\mathrm{JS}\big(p_B^{\mathrm{content}}(c),p_B^{\mathrm{content}}(T_l(c))\big)\right].
\]

`p_B^{content}` 是一个只用于报告和鲁棒性检查的控制头，不等于把正式 B 强行格式不变。若注释、变量名或空白改变创建方式语义，就不把它们当作 B/C 的正对。模型结果必须同时报告原始视图、格式化视图和“格式完全删除/规范化”视图，避免一个总损失掩盖任务冲突。

### 4.4 建议的最小联合目标

先用同一预算的 CodeT5 微调建立主基线，再逐项增加可审计对象：

\[
L=L_A+\lambda_B L_B+\lambda_C L_C
 +\lambda_r L_{\rm response}+\lambda_v L_{\rm selective-view}+\lambda_h L_{\rm hard}.
\]

其中 `L_A/L_B/L_C` 是真实 A/B/C 标签交叉熵；B 含 Human 类，C 只使用有可靠创建协议的样本。`L_response` 不是虚构的 post-training label，而是对来源差异和安全变体响应的监督/校准：

\[
L_{\rm response}=\mathrm{CE}(q_{fg}(c),s_{fg})
 +\eta\,\mathrm{MSE}\left((a_{fg}(c)-a_{fg}(T(c))),\widehat{\Delta}_{fg,T}\right),
\]

第一项学习匹配来源的行为差异，第二项只在 parent 配对和变换安全证据完整时启用；没有配对时只报告 `a`，不把它写成机制 delta。`L_{\rm selective-view}` 只作用于预注册的 A/控制头，不强迫 B 抹掉真实 family style；`L_hard` 使用同 task、同语义簇且来源/长度匹配的难负样本。

主批次应包含：`CodeT5`、`CodeT5+response`、`CodeT5+response+layout`、`CodeT5+response+layout+AMMC/selective-view`，以及 `CodeT5+layout` 和 source-label shuffled 控制。每个配置同 backbone、窗口、行数、seed 和预算；若 `response` 不超过直接 CodeT5，中心实例化就没有增量，不能靠再加容量、温度、轮数或损失项挽救。若只在原始视图有效，收缩为来源探针；若在格式化、task-heldout 和 model-heldout 仍有效，才支持“代码条件的后训练相关差异”叙事。


## 5. 数据重构：把反捷径变成因子设计

### 5.1 记录真实创建过程

每条记录至少需要 `task_id、language、project/lineage、human_or_ai、family/source_unit、model/checkpoint（若可得）、agent/runtime、prompt_version、tool_use、formatter、creation_type、solution_sha256`。缺失字段保留为 unknown，不用目录名推断 family。Human 行要有来源与任务证据；只有 repository 而无同题 prompt 的人类代码不能伪装成同题配对。

建议把 AI 采样组织成小型 factorial 设计：同一 task、相同接口和资源预算下，改变 family/checkpoint、agent runtime、prompt 模板和 formatter 中尽可能少的因素。实际不可控的因素要进入 provenance，而不是在公式中假设“旗舰模型 base 相同”。Human、Machine、Hybrid、Adversarial 只在确有创建记录时入 C；普通去注释/改名/格式化视图继承 parent 标签，不制造新的 creation type。

### 5.2 切分顺序

先按 `task/project/solution-cluster` 冻结 train/dev/test，再做增强。exact、规范化空白、去注释/字符串骨架、AST/CST 近重复必须在同一簇。B 的 generator/family-heldout 作为独立折；A/C 同时报告 task-heldout 和外部来源测试。旧 test 不因新方案被重新读取。

### 5.3 AMMC 类增强的正确位置

对 train parent 独立采样注释处理、轻度安全 whitespace 变化、作用域安全 identifier rename；保存 `parent_id、transform_mask、before/after hash、CST/AST hash、拒绝原因`。原视图与变体按 label、family、language、长度桶配平。dev/test 保留原视图，并另建格式化 stress set。

增强的目的不是假设这些特征都是“坏捷径”，而是检验模型是否依赖不可迁移的表面工件：

* `T_layout`：测试 A 在 formatter、tab/space 统一和行尾空白清理后是否保持；
* `T_comment/name`：测试去注释或安全改名后的检测和 B 稳定性；
* `T_semantic`：只在确实保持语义和创建标签的变体上测试；
* `T_origin`：不把普通变体拿来冒充 Hybrid/Adversarial。

每个变换先通过格式/语法审计，再进入训练或 stress set。Python 缩进、字符串、宏和反射相关位置必须拒绝不安全候选。UIT-AMMC 论文将结构化格式特征、随机增强和模型训练结合起来，说明这条路线值得借鉴；其竞赛分数或具体结论不直接移植到 d-det。

## 6. 反捷径与“涌现特征”的证据链

每个正式模型都要有四层证据，而不是只报一个主分数：

1. **控制模型：** metadata、length、lexical TF-IDF、AST/CST shape、纯手工 format；这些用来知道主模型是否只是复现简单统计。
2. **输入消融：** 移除 layout、规范化 layout、移除注释/名字、短代码/长代码、跨语言；比较相同 CodeT5 参数预算。
3. **反事实应力：** 对 parent 配对视图算预测变化、校准变化和错误交集；A 与 B 分别报告，不用总平均遮住差异。
4. **来源外推：** task-heldout、project-heldout、family-heldout、formatter-heldout 至少各有一种，bootstrap 单位为 task/project，而非代码行。

“更强特征”只有在通过输入消融、反事实应力和来源外推后才算涌现；单项 probe 的高 AUROC 只能说明数据中有信号。特别是词法/空白 probe 很高时，不能简单把它们全删掉：它们可能是实际后训练痕迹，也可能是采集工件。应让主模型在“原始、格式化、跨来源”三种测试上分别回答两者的区分。

## 7. 实验顺序和停止规则

### 阶段一：本机完成

先从 100k+ 行入口构建 provenance、task/file/solution split、CST/layout 特征和父子变体索引；生成控制模型分数、长度分层表、tokenizer/布局可恢复性和 view-probe。16k 小池只做代码 smoke。此阶段不需要 AutoDL，也不读取旧 test。

### 阶段二：一次主线 GPU 批次

上传一个冻结的 100k+ 行包和一个 manifest，一次性包含 response、layout、AMMC/selective-view、完整 CodeT5 基线、source-label shuffled 控制、至少两个 model/source-heldout 折、完整 seed 集合、长短代码切片、原始/格式化 stress 评估和统一日志。闭源旗舰只需提供版本化最终输出与 provenance；公开谱系校验若有则作为同批可选诊断，不得阻塞主批次。不要再把服务器工作拆成一串只回答一个小问题的收发记录。

### 阶段三：只在主线有增量时扩展

若 layout 分支在 CodeT5 基线之上、且在格式化和 task-heldout 上仍保留增量，再做 B/C 的联合头和 family-heldout；若只在原始随机 split 增加，则退回数据和切分。若 AMMC 降低原始分数但改善外部格式化稳健性，分别报告 trade-off，不以单一总分决定成功。

停止条件是“可证伪的增量没有出现”，不是“再试一个损失”。一旦主配置在两个折和多个 seed 上都不超过同预算 CodeT5，关闭该分支并保留结果；不增加容量、温度、轮数或复杂后处理来挽救它。

## 8. 论文中可以安全主张什么

在当前证据基础上，最稳妥的论文主张方向是：

* 代码来源检测和含 Human 的家族归因是不同但共享输入的任务；Human 不是一个需要从 family head 删除的噪声类。
* 代码格式是可观察的后训练相关行为通道；它既可能提升检测，也可能在 formatter 或跨来源条件下失效，因此必须作为输入消融和鲁棒性因素研究。
* 受控的代码变体可以检验模型是否依赖表面工件，但不能单独证明 post-training 因果，更不能自动改变创建方式标签。
* d-det 的新模型若胜出，首先应称为“代码条件下的来源/创建方式判别增量”；只有在模型谱系和环境真正受控时，才进一步讨论后训练机制。

## 9. 需要保留的主要风险

* 旗舰模型的 base 并不自动相同；闭源模型、不同 tokenizer、工具链和 prompt 都可能贡献差异。
* 代码格式与任务难度、语言、项目和长度高度相关；格式分支并不天然等于纯后训练信号。
* tokenizer 能编码 tab 或行尾空格，不保证 pooled representation 保留全文件布局；长代码处理是独立变量。
* B 的 Human-inclusive label 若来源证据不足，会把“数据集风格”误写成家族归因；AI-only 诊断不能替代 B。
* 无监督或弱约束的“正交潜变量”不能被解释为已分离出的 reward、base 或 post-training 坐标。
* 旧实验的负结果仍然重要：它们告诉我们哪些旧输入、旧 split 和旧损失没有产生增量，不应被新文档静默抹掉。

## 10. 本讨论稿引用的入口文献

* [Agrahari et al., Osint at SemEval-2026 Task 13](https://aclanthology.org/2026.semeval-1.360/)：同时讨论二分类检测和包含 Human 的多源归因，并强调长上下文、分布感知采样和噪声鲁棒性；这说明任务形状本身不能作为本文创新。
* [MINDS at SemEval-2026 Task 13](https://aclanthology.org/2026.semeval-1.386/)：把检测、归因和 Hybrid/Adversarial 放在分布偏移下比较，支持本文把 formatter/family 外推列为必要验证条件。
* [CoDet-M4](https://aclanthology.org/2025.findings-acl.550/)：多语言、多生成器和跨域泛化是已有重要基线，本文不能把“多语言/OOD”单独包装成贡献。
* [MALTO at SemEval-2026 Task 13](https://aclanthology.org/2026.semeval-1.304/)：已有工作使用 canonicalization、增强、hard-negative 和 curriculum；本文需要避免把这些工程组件的简单组合当作方法创新。
* [Pham et al., UIT-AMMC at SemEval-2026 Task 13](https://aclanthology.org/2026.semeval-1.60/)：结构化格式特征、随机增强和代码检测的直接相关工作；论文摘要报告其使用格式统计、增强和 CodeT5 类模型，但本文不移植其竞赛数字。
* [Nirob et al., Whitespaces Don’t Lie](https://arxiv.org/abs/2601.19264)：展示空白/缩进特征与 embedding detector 可能各自携带信号，支持把格式当作可检验通道，而不是未经审计的结论。
* [Caliskan-Islam et al., De-anonymizing Programmers via Code Stylometry](https://www.usenix.org/system/files/conference/usenixsecurity15/sec15-paper-caliskan-islam.pdf)：说明布局、词法和语法风格都可能参与代码归因。
* [Bogomolov et al., Authorship Attribution of Source Code](https://sback.it/publications/fse2021.pdf)：提醒合成数据上的高归因分数在更现实的数据上可能明显下降，支持 project/lineage 切分和真实来源记录。
* [CodeT5: Identifier-aware Unified Pre-trained Encoder-Decoder Models](https://arxiv.org/abs/2109.00859)：作为完整 CodeT5 微调基线的模型依据。
* [Locatello et al., Challenging Common Assumptions in the Unsupervised Learning of Disentangled Representations](https://proceedings.mlr.press/v97/locatello19a.html)：说明无监督 disentanglement 不能凭损失名称获得可识别语义，支持本稿对“潜变量分离”主张的收缩。
* [Orel et al., AICD Bench](https://arxiv.org/abs/2602.02079)：公开基准约 2M 代码样本、77 个生成器、11 个 family 和 9 种语言，并把 robust binary、family attribution、Human/Machine/Hybrid/Adversarial 三种任务并列；其公开 parquet 的当前入口仍只暴露 code 与 numeric label，因此本项目保留原始标签 ID，不擅自恢复 family 名称。

## 11. 讨论结论

最值得推进的不是再给旧 C0–C3 加一个分离项，而是把 d-det 改造成一个黑盒可执行、机制边界诚实的主线：同预算完整 CodeT5 作为底座，学习同一代码条件下的多来源相对行为和变体响应，增加可审计的代码布局通道，以含 Human 的 B 和真实创建历史的 C 共同约束标签语义，用 AMMC 类变体测量表面依赖，并在 task/project/model/formatter 外推上验证。主线按旗舰 base 差异可忽略的工作假设推进；公开 base→post 谱系只承担后补机制校验，不再作为旗舰实验前置条件。这个设计既允许格式成为真正有用的后训练相关特征，也允许实验证明它只是数据工件；两种结果都比把它预先规定为“捷径”或“因果坐标”更有论文价值。

本稿现在只作为讨论起点。下一步应先在本机把 provenance、CST/layout 表示和四个最小配置的 manifest 设计清楚，再决定是否生成新的数据包和 AutoDL 批次；旧文档和旧结果在此之前保持原样。
